PDW (Pulse Descriptor Word) Fields

Carrier Frequency (fc)
The radio frequency the pulse was transmitted on, in MHz (megahertz). Used for spectral band mapping and detecting frequency-agile emitters.
Pulse Width (PW)
How long a single pulse lasts, in microseconds (µs) — or nanoseconds (ns) in the Interleaved Dataset generator, which works at finer time resolution. Helps isolate the emitter's modulation mode.
PRI (Pulse Repetition Interval, ΔToA)
Time between consecutive pulses from the same emitter, in microseconds (or nanoseconds for the Interleaved Dataset). Reveals the emitter's timing pattern — see PRI Modulation Patterns below.
PRF (Pulse Repetition Frequency)
The reciprocal of PRI (PRF = 1 / PRI), in Hz — how many pulses per second the emitter transmits. Shown on the Analytics page as an alternative view of the same timing information PRI carries.
Time of Arrival (ToA)
Precise timestamp the pulse was received, in nanoseconds. Used to reconstruct interleaved pulse trains from multiple emitters (deinterleaving) and to derive PRI as the delta between consecutive ToAs.
Rise Time
How quickly the pulse reaches full amplitude, in nanoseconds — a subtle transmitter hardware fingerprint.
Angle of Arrival (AOA)
The bearing, in degrees, the pulse's wavefront arrived from (as measured by a hypothetical multi-element receiver array). Used only by the Interleaved Dataset's classical (DBSCAN) deinterleaving method as an extra clustering feature — the Classification Dataset does not use it, since AOA identifies platform bearing, not emitter identity.
Duty Cycle
Fraction of time the emitter is actually transmitting: Pulse Width / PRI. Low duty cycle (search radars, long PRI) vs. high duty cycle (illumination/track radars, short PRI) is itself a strong Operating Mode signal. A model input — computed on the fly inside normalize_pdw() from the Pulse Width and PRI already provided, since it's a genuine PW×PRI interaction a single linear classifier layer can't otherwise construct on its own. Also shown on the Analytics page as a percentage.
Inter-Pulse Interval (raw stream)
The literal ToA gap between any two consecutive pulses in the raw, interleaved (multi-emitter) receive stream — not the same as PRI, which is the gap between two pulses from the same emitter. Deinterleaving is precisely the problem of recovering per-emitter PRI out of this mixed raw sequence.

PRI Modulation Patterns

The six standard radar PRI modulation types from ESM / PRI-recognition literature — what real PRI-transform deinterleaving techniques (CDIF/SDIF) and PRI modulation recognition research actually discriminate between. Every simulated emitter class is assigned one of these.
Constant
PRI stays fixed at a single value, pulse after pulse — the simplest pattern.
Jittered
PRI varies randomly (small Gaussian noise) around a fixed mean, pulse to pulse — used to resist certain jamming/deception techniques.
Staggered
PRI cycles through a small number of fixed, discrete values in a fixed repeating order (e.g. A-B-C-A-B-C...) — used to resolve range/velocity ambiguities.
Sliding
PRI ramps continuously up and down between a minimum and maximum over time (a triangular sweep), rather than jumping between discrete values.
Wobulated
PRI oscillates smoothly (sinusoidally) between a minimum and maximum — similar intent to sliding, different waveform shape.
Dwell-and-Switch
PRI holds at one fixed value for a long block of pulses, then jumps to a different fixed value for the next block, and so on — distinct from staggered, which switches every pulse rather than dwelling.
In the Classification Dataset (independent, non-sequential samples), only the steady-state distribution shape of each pattern can be represented — staggered and dwell-and-switch are statistically indistinguishable without temporal order, so both draw from the same multi-modal distribution there. In the Interleaved Dataset and Live Feed (real pulse trains with genuine time ordering), all six patterns are generated as true temporal sequences and are fully distinguishable — visible directly in the Analytics page's Pulse Train Timeline.

Operating Modes

Real multifunction radars don't emit with fixed parameters — they switch between modes that change frequency, pulse width, and PRI together, generally escalating as a target is acquired and tracked (the "war mode" search → lock-on progression), though an emitter can also lose lock and de-escalate.
Search
Wide-area scanning for any target. Longest PRI, widest pulse width, slightly lower frequency, lowest duty cycle — optimized for range/coverage over precision.
Acquisition
A candidate target has been detected; the radar narrows its focus to confirm and localize it. Baseline (1.0×) frequency/PRI/pulse-width multipliers — the reference mode the other three are defined relative to.
Track
Continuously following a confirmed target. Shorter PRI, narrower pulse width, slightly higher frequency, higher duty cycle than acquisition — trades coverage for update-rate precision.
Illumination
Highest-fidelity lock-on, typically immediately preceding weapon guidance or engagement. Shortest PRI, narrowest pulse width, highest frequency and duty cycle of the four modes — the most operationally significant mode to detect promptly.
Mode Diversity vs. Mode Persistence
The Classification Dataset draws each sample's mode independently (population diversity — good for training a classifier to recognize any mode in isolation). The Interleaved Dataset and Live Feed instead give each emitter persistent state: it dwells in one mode for a block of consecutive pulses (15–60 pulses) before a biased random transition (50% escalate, 30% de-escalate, 20% jump) decides the next mode — so the escalation is something you can actually watch unfold over time on the Live Simulation page, not just a diversity statistic.

Dataset Generation Pipelines

The Dataset page produces two independent artifacts for two different purposes — never cross-used.
Classification Dataset
Independent, labeled PDW rows (no time-of-arrival ordering) used to train and test the classifier + open-set model. Each row is one emitter's PDW at one random Operating Mode draw. Includes deliberately held-out classes (never trained on, for honest open-set evaluation) and a configurable percentage of unstructured OOD noise (see Noise Percentage below).
Interleaved Dataset
A simulated raw receive stream: multiple emitters' pulse trains mixed together in true time-of-arrival order, each with real per-emitter PRI Modulation Patterns and persistent Operating Mode transitions. Used exclusively for the Deinterleaving demo (Dataset page) and as a Live Simulation replay source — never used to train the classifier, since the point is to test whether pulses can be correctly re-grouped by emitter without knowing the classifier's labels.

Model & Hyperparameters

Neural Model Backbone
The shared feature extractor before the two output heads. 1D-CNN (1-Dimensional Convolutional Neural Network) focuses on local/spatial pulse patterns; Transformer focuses on sequence relationships; Hybrid combines both.
Distance Metric
How similarity between two embedding vectors is measured in Qdrant: Cosine (angle between vectors, scale-invariant), Euclidean (straight-line distance), or Dot Product (unnormalized similarity).
Inference Engine
PyTorch Native runs the model directly; ONNX (Open Neural Network Exchange) Runtime runs a portable exported version of the same trained weights — both should produce numerically identical outputs. ONNX requires a completed training run to export from.
Learning Rate
Step size for the Adam optimizer during training. Too high can destabilize training; too low makes it slow to converge.
Triplet Margin (α)
Minimum gap the triplet loss enforces between "same-class" and "different-class" embedding distances. Larger margins push classes further apart in embedding space, but can make the loss harder to satisfy.
Min Classifier Confidence
Softmax confidence threshold. Below this, a pulse is treated as low-confidence regardless of the Qdrant distance, and rejected as OOD (Out-of-Distribution) noise.
OOD Distance Threshold
Qdrant distance threshold. Above this, the nearest known prototype is considered too far away to trust — the pulse is flagged as anomalous rather than a confident match.
RPL Loss Weight
How strongly the auxiliary Reciprocal Points Learning (RPL) objective shapes the shared embedding space during training, relative to the primary classifier + triplet losses (default 0.1, deliberately modest so RPL can't destabilize the proven primary training).
Enable Adversarial Training (ARPL)
Upgrades RPL to the full ARPL (Adversarial Reciprocal Points Learning) mechanism: a generator network adversarially synthesizes "confusing" embeddings targeting each known class, and the classifier is trained (in a min-max game) to keep rejecting them as open-space even as the generator tries to make them pass as genuine. Tightens the decision boundary beyond RPL's passive open-space margin loss, at the cost of a less stable, sometimes slower-converging run. Off by default — toggle it and retrain to get a genuine RPL-vs-ARPL comparison across two separate runs (both show up in Run History, each labeled with which mode produced its AUROC number).
Dataset Seed
Controls both which radar-family archetypes (frequency/pulse-width/PRI/rise-time) get generated and which classes are randomly held out — a fresh seed is drawn every training run for genuine diversity. Testing's auto-generate mode reuses the exact seed from your last training run so it evaluates the same population the model was actually trained on, not a different one.

Qdrant Vector DB (Database) Parameters

HNSW (Hierarchical Navigable Small World) M — connectivity
Number of graph connections per node in the HNSW index. Higher = more accurate search, more memory.
ef_construct
Search breadth used while building the HNSW index. Higher = better-quality index, slower to build.
Quantization Mode
Scalar (SQ8 — 8-bit Scalar Quantization) compresses each vector component to an 8-bit integer; Binary compresses to 1 bit per component. Both trade some precision for memory/speed — intended for edge (low C-SWaP: Cost, Size, Weight, and Power) deployment.

Training & Validation Metrics

Closed-Set Accuracy
Fraction of pulses from known (trained-on) classes that the classifier head predicted correctly.
Open-Set AUROC (Threshold)
AUROC (Area Under the ROC — Receiver Operating Characteristic — Curve) for using embedding-distance-to-nearest-centroid as an anomaly score, evaluated on classes held entirely out of training. 1.0 = perfect separation of known vs. unknown; 0.5 = no better than random guessing. This is the method the live Fusion Verdict logic actually uses (compared against the OOD Distance Threshold). Each class contributes up to 3 centroids (via K-means clustering over that class's embeddings), not one mean — a class whose true population spans multiple Operating Modes can have sub-clusters far enough apart that a single mean would land in the empty space between them, making genuine same-class samples look falsely anomalous. "Distance to nearest known" now means nearest of all sub-centroids across all classes, not nearest single mean per class.
Open-Set AUROC (Reciprocal Points)
A second, independently-trained open-set method — RPL (Reciprocal Points Learning) — scored the same way (AUROC) on the exact same train/val/holdout split, so the two numbers are directly comparable. Instead of representing each class by what it IS (a centroid), RPL learns a "reciprocal point" per class representing what it ISN'T, plus a learned per-class radius bounding how far a genuine sample of that class may drift from its own reciprocal point. Farther-than-radius = flagged unknown. This gives each class a finite, bounded acceptance region instead of softmax's open-ended one — the mechanism behind the ARPL (Adversarial Reciprocal Points Learning) line of current open-set radar literature. Trained jointly with the main model as an auxiliary objective (a small fixed loss weight, so it doesn't destabilize the primary training) — it does not replace the threshold method, both are reported from the same run.
Holdout Classes
Radar classes deliberately excluded from training so open-set detection can be measured honestly — the model has genuinely never seen them, unlike ordinary noise.
Noise Percentage (Unstructured OOD)
Fraction of unstructured, agile OOD (Out-of-Distribution) pulses (no coherent class structure at all — not just "a radar type we didn't train on") mixed into the open-set evaluation pool alongside the holdout classes. Real intercepted environments contain both novel-but-structured emitter types and outright junk/noise signals, so a thorough open-set evaluation should include both. Set on the Dataset page when generating the classification dataset; Testing's auto-generate mode reuses the exact percentage the current model was trained against, same as it reuses the dataset seed and ranges.
Training Loss
Sum of cross-entropy (classifier head) and triplet loss (metric head) on each training batch, averaged per epoch. Trending down means the model is fitting the training data; a plateau means further epochs are giving diminishing returns.

Deinterleaving Metrics

Classical Method
DBSCAN (Density-Based Spatial Clustering of Applications with Noise) clustering directly on standardized frequency/pulse-width/AOA (Angle of Arrival) — a feature-space clustering baseline, not a full PRI-transform (CDIF/SDIF: Cumulative/Sequential Difference Histogram) deinterleaver. Requires no training and no ground truth — works on any uploaded data, real or synthetic.
Deep Metric Learning Method
Trains a small embedding network (triplet loss — same idea as the classifier's metric head, applied per-pulse instead of per-class) using an MLP (Multi-Layer Perceptron) on this dataset's own ground-truth emitter identities, then runs the same DBSCAN clustering in that learned embedding space instead of raw standardized features. Mirrors the transformer-based deep metric learning approach in current radar pulse deinterleaving research, using a lightweight MLP instead of a full transformer to stay CPU-fast. Ground truth trains the embedding only — the clustering step is exactly as unsupervised as the classical method, and only synthetic data (with known emitter_instance_id) can train it; uploaded real captures with no ground truth can only use the classical method.
Predicted Tracks
Number of distinct emitter clusters the clustering algorithm found in the interleaved pulse stream — no ground truth used at this step, regardless of method.
Adjusted Rand Index (ARI)
Standard clustering-agreement score comparing predicted clusters to the true emitter-instance labels. 1.0 = perfect agreement, 0.0 = no better than random clustering. Computed identically for both methods, so it's a fair head-to-head comparison.

Analytics Page Metrics

Summary Statistics
Standard descriptive statistics (count, mean, standard deviation, min, quartiles, max) per numeric column — the pandas describe() view.
Correlation Heatmap
Pairwise Pearson correlation between numeric PDW features, colored by strength/direction — reveals redundant or coupled features (e.g. pulse width and duty cycle).
Class Balance / Class Diversity
Row count per class label, plus three population-health stats: Classes (distinct label count), Normalized Shannon Entropy (0–1; 1.0 = perfectly even class distribution, lower = imbalanced), and Max/Min Class Ratio (imbalance ratio — how many times larger the biggest class is than the smallest).
Frequency Band Breakdown
Row count per standard radar frequency band (L/S/C/X/Ku/K/Ka — see Radar Frequency Bands above) — the classic first-pass ESM spectrum occupancy view.
PRI Pattern Distribution
Row count per PRI Modulation Pattern type (see above) present in the loaded dataset.
Pulse Train Timeline
Scatter plot of Time of Arrival vs. Carrier Frequency, colored by emitter/class — the classic real-time ESM console view. Overlapping pulse trains from different emitters are exactly what makes deinterleaving hard; PRI Modulation Patterns (staggered, sliding, etc.) become visible as literal geometric shapes along the time axis.
PCA (Principal Component Analysis) — Raw Features
2D projection of the raw physical PDW features, before any model is involved — the baseline separability question every classification task starts with. "Explained variance" states how much of the original feature-space spread the 2 plotted axes actually capture.
PCA — Learned Embedding
2D projection of the model's actual learned embeddings for this data — the real answer to "did training separate these classes?", not just an accuracy number. Only available after a model has been trained.
Silhouette Score
Cluster-separation quality score, computed per class label in either the raw feature space or the learned embedding space. Ranges roughly -1 to +1: near +1 means each class is tight and well-separated from the others, 0 means classes overlap, negative means points are on average closer to a different class than their own. Comparing the raw-feature score to the embedding-space score is a direct, quantitative measure of how much the trained model actually improved class separability.
Duty Cycle (%) / PRF (Hz)
See PDW Fields above — both are alternative views of the same pulse-timing information already carried by Pulse Width and PRI.

Fusion Verdicts & ECM (Electronic Countermeasures) Actions

Every pulse gets one verdict, produced by combining the classifier head's confidence with the Qdrant embedding-distance check — neither signal is trusted alone.
VERIFIED_KNOWN_TARGET
High classifier confidence AND small Qdrant distance — the model is confident and the embedding genuinely resembles a known prototype. ECM action: MONITOR_ONLY (no active response needed for a verified, already-known emitter).
UNKNOWN_THREAT_ANOMALY
High classifier confidence BUT large Qdrant distance — the classifier is (over-)confident, yet the embedding doesn't actually sit near any known prototype. Treated as a possible novel/spoofed emitter. ECM action: AUTOMATED_JAMMER_ENGAGED (treat as a live threat pending human confirmation).
OOD_NOISE_REJECTED
Low classifier confidence — the model itself isn't sure, regardless of distance. ECM action: ELINT_LOGGING (logged for later Electronic Intelligence analysis rather than acted on immediately).

Live Simulation

Replay Source
Interleaved Dataset replays the Dataset page's deinterleaving demo file in real time-of-arrival order — its emitter_class labels live in a different, unrelated label space from the classifier's actual trained classes, so predictions can't be checked against ground truth (visualization/demo value only). Classification Dataset instead replays the exact schema and label space the model was trained on, shuffled into a live-feeling order — every prediction gets a real, verifiable Correct/Incorrect flag: for known rows, whether the predicted class matches the true label; for held-out/noise rows, whether the fusion verdict correctly avoided confirming them as a known target. Live Feed generates genuinely continuous, unlabeled pulses on the fly (nothing read from or written to disk), for up to 15 minutes — a small set of simulated emitters carry persistent state across the session, each dwelling in one Operating Mode before transitioning (generally escalating, occasionally losing lock and de-escalating), so a real search → track → lock-on progression is something you can actually watch unfold — but nothing about which emitter, class, or mode is ever sent to the client or scored, matching genuine real-time operation where no ground truth exists at all. Configure its population via the Advanced: Population Ranges button (shown only for this mode).
Live Threat Log
The primary operator-facing view — the last 30 detections, newest first, colored by verdict. Modeled on real EW console research (e.g. AN/SLQ-32 human-factors studies): operators need to track multiple concurrent detections at a glance, not just the single latest reading.
Situational Awareness Tiles
Running session totals — Pulses Processed, Verified Known, Unknown Threats, Rejected/Noise, and (Classification Dataset replay only) Live Accuracy against ground truth. Gives an at-a-glance summary without having to mentally tally the scrolling log yourself. Double-click any tile to open a detail table of every underlying pulse in that category (predicted class, confidence, verdict, ECM action, and all PDW input features) — useful for inspecting exactly what drove the aggregate count.
Session Persistence
Live Simulation data (stats, threat log, charts, and the tile detail tables) is kept in the browser's session storage and automatically restored if you navigate to another page and back, so switching tabs to check Analytics or Help doesn't lose your run. This is per-browser-tab only — it clears when the tab is closed, and does not survive a full server restart. Starting a new simulation always clears it for a clean run.
